# 智答 · 学习通答题助手

> Chrome 扩展（Manifest V3）· WXT + TypeScript · 无后端 · API Key 只存本机

📦 **直接下载安装包**（无需构建）：[Releases → 最新版](https://github.com/bybixi/chaoxing-answer-assistant/releases/latest) → 下载 `zhi-da-v1.0.13-chrome.zip` → 解压后在 `chrome://extensions` 里「加载已解压的扩展程序」。
- 安装前请务必打开浏览器的**开发者模式**，否则可能**无法加载**该扩展程序。

自动侦测作业/考试页面的题目 → 调用**你自己配置的** OpenAI 兼容接口求解 → 自动回填 → 依靠平台自身的实时保存落盘。

**只回填，不点提交**（自动提交开关默认关闭，且不建议打开）。

## 特性

| 能力 | 说明 |
|---|---|
| **两种页面形态自适应** | 逐题渲染页（自动逐题跳转遍历）与整卷铺开页（就地作答，**零跳转**）自动识别并分流 |
| **只答当前题** | 补答留空题时不必整卷重跑：翻到那一题点一下即可 |
| **四道准确率防线** | 结构化输出 → 本地严格校验 → 校验失败带反馈重试 → 置信度阈值 + 低置信度**独立复核** |
| **宁空不错** | 把握不足就留空并写明原因，绝不硬猜；浮球上能看到每一题的处置原因 |
| **并发调度** | 并发数、请求间隔随机抖动、每分钟上限、指数退避重试，全部可调（纯逻辑模块，有单测） |
| **状态机在 Service Worker** | 跨页面跳转不丢状态；SW 被浏览器回收后可从会话存储恢复 |
| **图片题支持** | 配了视觉模型后，题干**与选项**图片（如公式选项）一起送模型 |
| **可拖动浮球 UI** | 拖动 + 自动吸边、可收起为贴边小角标、位置跨刷新记忆 |
| **回填即校验** | 每次回填后读回页面真实状态校验，不一致就报失败，而不是假装成功 |

## 架构速览

```
┌──────────── Service Worker（指挥所，唯一有状态的地方）────────────┐
│  RunState: collect → solve → fill                               │
│  solve: 并发调度器 → 逐题调用 AI（抓图→提示词→校验→重试→复核）      │
│  状态持久化到 chrome.storage.session（SW 被回收后可续命）          │
└─────────┬─────────────────────────────────────┬─────────────────┘
          │ WORK_STEP（PARSE / FILL 指令）        │ ENGINE_STATE（进度广播）
          ▼                                     ▼
┌───────────────────────────┐        ┌───────────────────────────┐
│ 内容脚本（无状态工人）      │        │ 浮球 UI（顶层，Shadow DOM）│
│ 解析当前题→上报→按指令切题  │        │ 进度/原因/开始/停止/只答当前题│
│ 取答案→回填→读回校验→上报    │        │ 拖动 / 吸边 / 收起           │
└───────────────────────────┘        └───────────────────────────┘
```

**为什么状态必须放在 Service Worker**：这类答题页每切一题就**整页跳转**，内容脚本连同内存一起销毁。把编排状态放 SW、内容脚本做成"做一件事就死"的无状态工人，是这套架构能跑通的关键。

## 快速开始

### 方式 A：直接下载发布包（推荐给只想用的人）

去 [Releases](https://github.com/bybixi/chaoxing-answer-assistant/releases/latest) 下载 `zhi-da-v1.0.13-chrome.zip`，解压到任意固定文件夹，然后跳到下面「2. 加载」。

> ⚠️ 发布包**不含固定公钥**，扩展 ID 由加载目录决定 → **更换文件夹会丢失已保存的配置**。需要固定 ID 见 FAQ 里那一节；换机/重装可用设置页的导出/导入配置。

### 方式 B：从源码构建（开发者）

```bash
# 环境要求：Node ≥ 20（建议 22 LTS）
npm install

# 若报 @rollup/rollup-win32-x64-msvc 缺失（npm 在 Windows 上的已知 bug）：
npm i -D @rollup/rollup-win32-x64-msvc && npm run prepare

npm run dev      # 开发模式（输出 .output/chrome-mv3，带热更新）
npm run build    # 生产构建
npm test         # 单元测试（调度器/答案校验/题型识别/重试/选择对齐）
```

### 2. 加载

打开 `chrome://extensions` → 打开右上角**开发者模式** → **加载已解压的扩展程序** → 选择 **`.output/chrome-mv3`** 目录（下载发布包的则选解压出来的文件夹）。

> ⚠️ 从源码构建时要选构建产物目录 `.output/chrome-mv3`，不是项目根目录（那里才有 `manifest.json`）。

### 3. 配置

点扩展图标（或「详细信息 → 扩展程序选项」）打开设置页：

| 字段 | 必填 | 说明 |
|---|---|---|
| API 地址 | ✅ | OpenAI 兼容端点，如 `https://api.deepseek.com`（带不带 `/v1` 均可） |
| API Key | ✅ | 只存本机 `chrome.storage.local` |
| 模型名 | ✅ | 文本模型，如 `deepseek-chat` |
| 视觉模型名 | 图片题必填 | 留空则含图题目自动留空（不猜） |
| 最低置信度 | | 低于此值不回填（默认 0.6），配合复核机制使用 |
| 并发数 / 间隔 / 每分钟上限 / 重试 | | 请求节奏控制，默认较保守 |
| 思考模式 + 强度 | | 先推理再作答，更准但更慢（默认开、强度 high） |
| 低置信度自动复核 | | 对没把握的题做一次**独立复核**，抢救 + 防错（默认开） |
| 自动开始 / 自动提交 | | 自动提交**默认关闭且不建议开启** |

## 使用

打开作业/考试页后，右下角出现浮球：

| 操作 | 效果 |
|---|---|
| 单击圆球 | 展开 / 收起面板 |
| 拖动圆球 | 移动位置，松手**自动吸附到最近一侧边缘**（位置跨页面记忆） |
| 双击圆球 | 收起为贴边小角标（半透明、不挡内容、运行时变绿） |
| 点小角标 | 展开回圆球 |
| **开始** | 按页面形态自动选择打法（见下） |
| **停止** | 中止本轮（就地作答模式会真正停掉调度器，不再继续发请求） |
| **只答当前题** | 只解析、求解、回填**屏幕上这一题**，不跳转、不动其他题 |

### 三种作答模式

| 模式 | 触发条件 | 行为 |
|---|---|---|
| **逐题模式** | 页面上有答题卡（一次只渲染一题） | 自动逐题跳转：遍历采集 → 并发求解 → 逐题回填 |
| **就地作答** | 题目一次性全铺在同一页（整卷预览/浏览） | 解析全部题目后就地作答，**一道题都不跳转** |
| **只答当前题** | 手动点击 | 只处理屏幕上当前可见的那一题（整卷页取视口中心那道） |

跑完后**务必自己核对一遍**，确认无误再决定是否提交。

## 常见问题（FAQ）

### 安装与权限

**Q：装好后页面上什么都没有？**
依次确认：① 加载的是 `.output/chrome-mv3` 而不是项目根目录；② 只在**作业/考试页面**生效，普通课程页与首页不会出现浮球；③ 打开 `chrome://extensions` 看扩展卡片有没有红字报错；④ 等页面完全加载后再等一两秒（内容脚本在 `document_idle` 注入）。
内容脚本用「角色识别」决定在哪个 frame 干活，**非顶层的普通 iframe 不注入任何 UI**，所以浮球永远只该有一个。

**Q：安装时提示"读取和更改您在 chaoxing.com 上的数据"，安全吗？**
这是**核心功能所需**：要在页面里读题目、填答案，就必须有该站点访问权。权限已压到最小（仅 `storage` + 必需域名），**没有** `<all_urls>`。若出现"在所有网站上读取数据"的提示，说明构建配置被改坏了。

**Q：工具栏图标点了没反应？**
图标点击的行为是打开设置页。若无反应，用「详细信息 → 扩展程序选项」。

### 运行期问题

**Q：点「开始」提示"答题卡里没有找到题目"？**
页面被判成**逐题模式**但找不到答题卡。① 等页面完全加载后再点；② 若这其实是"整卷铺开"页面，看浮球诊断行是否显示"答题卡 0"——那本应走就地作答，属形态识别偏差，需要调整 `detectPageShape()`。

**Q：点「开始」提示"没检测到题目"？**
确实是答题页但一个题目容器都没解析到：多半页面还在渲染，或平台改版导致选择器失效。先刷新重试；仍不行则是改版问题，需更新 `entrypoints/content/parse/selectors.ts`。

**Q：整卷页面漏了几道题？**
浮球橙色区会明确提示「⚠️ 疑似漏题：只解析到 N 题，侧栏显示共 K 题」。这是**懒渲染**导致的：题目随滚动才生成，未滚到的部分 DOM 里根本不存在。程序已在解析前自动滚动催熟；若仍提示，说明页面渲染比滚动慢——**再点一次「开始」**即可（那时题目已加载完）。

**Q：整卷页面报"未知题型，无法校验"？**
题型识别失败。判定题型有三重来源（题型徽标 → 隐藏域 → 结构推断），通常能兜住；若仍失败说明页面结构特殊。可先用「只答当前题」逐题处理，并把浮球上的诊断信息提 issue。

**Q：卡在"正在并发求解…"不动了？**
① 思考模式下单题可能耗时 30s+，先耐心等；② 程序已给每个请求加 **120 秒超时**，超时后按设置重试；③ 长时间无进展就点「停止」，看浮球原因列表；④ 若原因列表为空，可能是后台 Service Worker 被回收，切一下标签页或刷新页面会自动恢复（状态存在会话存储）。

**Q：大量题"回填失败：answer 值「0」未包含 X"？**
历史版本的已知缺陷（误取了页面的状态标志域而非答案域），**v1.0.13 已修**，请更新到最新版。

**Q：多选题答案比预期多了几个选项？**
历史版本的 toggle 语义缺陷（页面选项是"再点一次取消"），**v1.0.13 已修**为「先取消多余、再补选缺失 + 集合精确校验」。

**Q：为什么大部分题都留空？**
按原因列表逐条看：
- `未配置 API` → 去设置页填地址/Key/模型；
- `置信度过低` → 模型自己没把握，属"宁空不错"的预期行为，可适度调低「最低置信度」或换更强模型；
- `题目含图片但未配置视觉模型` → 补上视觉模型名（含公式的题很多都是图片）；
- `HTTP 401/403` → Key 无效或无权限；
- `HTTP 429` → 触发限流，降低并发数或每分钟上限；
- `HTTP 404` → **API 地址写错**：注意别重复写 `/v1`（程序已处理 base 以 `/v1` 结尾的情况）。

**Q：简答题（富文本编辑器）没填上？**
富文本（UEditor 类）是最脆弱的一环：它不是普通 `textarea`，直接赋值无效。程序采用多级降级（写编辑器 iframe 内容 + 触发同步事件 + 回写底层 textarea），仍失败会明确报错。**该路径尚未在真实简答题上充分验证**，若提示"已写入编辑器，但未找到底层 textarea 同步（提交前请肉眼确认）"，请务必人工确认。

**Q：整卷预览页能不能作答？**
取决于该页是否可编辑。若浮球报"点击后选项未变为选中态"，说明是**只读预览页**，只能在正式答题页作答。

**Q：换了文件夹/重装后 API Key 不见了？**
未打包扩展的 ID 由**加载目录路径**推导，而 `chrome.storage` 按 ID 隔离 → 换目录 = 换 ID = 配置全丢。
本项目内置「固定扩展 ID」方案：把 RSA 公钥写进 `manifest.key`，ID 就与路径解耦。仓库出于隐私考虑**不含公钥**（它绑定具体扩展实例身份），可以自己生成：

```bash
node tools/gen-ext-key.mjs   # 生成密钥对，公钥写入 .keys/public-key.txt（已 gitignore）
npm run build                # 之后构建出的扩展 ID 就固定了
```

设置页也提供**导出 / 导入配置**，换机、重装可一键迁移。
⚠️ 给已在用的扩展补上 `key` 会让 ID 变化一次，需用导出/导入迁一次配置。

**Q：会不会自动帮我提交？**
不会。自动提交开关**默认关闭且不建议打开**。程序只回填，提交由你手动决定。

**Q：题目内容会不会被上传到第三方？**
会发送到**你在设置里配置的那个 AI 接口**——这是工作原理，无法避免；除此之外无任何外发行为。API Key 只存本机。如果不希望题目外发，请不要配置 API 或不要使用本项目。

**Q：支持别的学习平台吗？**
目前只适配该平台的两类答题页。扩展到别处主要改 `parse/selectors.ts` 与解析逻辑，调度、校验、UI 部分可直接复用。

### 排查三步法

遇到异常按这个顺序收集信息，能定位绝大多数问题：

1. **看浮球诊断行**：点「开始」时显示 `检测：容器 N / 答题卡 M / 下一题按钮 有|无 → 模式`，直接说明程序认为这是什么页面。
2. **看浮球原因列表**（橙色区域）：每题留空/失败的具体原因都在这里。
3. **跑自检脚本**：
   ```bash
   npm test                          # 逻辑层是否健康
   node tools/audit-fixes.mjs        # 历史缺陷修复是否仍在位（逐条核验）
   node tools/verify-bundle.mjs      # 构建产物里是否真含关键逻辑
   ```

## 已知限制

- **平台改版即失效**：页面结构一变解析就失败。适配集中在 `selectors.ts` 与解析层，无需动调度/UI。
- **旧版整卷作业页路径未经实测**：其选择器为社区参考值，未在真实页面校准（见 `selectors.ts` 注释）。
- **简答题富文本回填**较脆弱（见 FAQ）。
- **只读预览页无法作答**。
- **反自动化机制**：本项目使用合成事件（`isTrusted` 为 false），若平台加入检测可能失效。
- **不追求满分**：设计取向是"宁空不错"——宁可少答，也不要答错。

### 工程要点（读代码前建议先看）

几条在真实环境踩出来的硬约束，代码都按它们写：

1. **Service Worker 会随时被回收**（空闲 30 秒）→ 状态一律进 `chrome.storage`，事件监听器必须**顶层同步注册**，异步 `sendResponse` 必须 `return true`。
2. **内容脚本在隔离世界**，看不到页面定义的全局函数，只能通过 DOM 事件驱动页面自身逻辑。
3. **同一份内容脚本每个 frame 都会跑一遍**，"全局 UI"必须显式限定在顶层文档，否则每个 iframe 都长一个浮球。
4. **往页面 DOM 插扩展内资源**（图标等）必须在 manifest 声明 `web_accessible_resources`，否则页面无权加载 → 破图。
5. **受控组件**直接改 `value` 不触发框架回调（看着填上、提交为空）→ 必须用原生 setter + 派发 `input/change`。
6. **回填后必须读回校验**，否则"以为填上了"的错误会一路带到提交。
